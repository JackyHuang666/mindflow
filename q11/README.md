# 學習地圖：11Q 學習成長雷達圖

右上角「學習地圖」按鈕開啟。依《MindFlow60_11Q 評量映射資料 V1.0》計分，畫出兩張雷達圖：

- **基礎能力**：HQ、EQ、NQ、AQ、IQ、MQ
- **進階能力**：TQ、CQ、RQ、FQ、SQ（基礎 6 項都有分數且平均 ≥ 60 分才解鎖；測試模式略過）

## 檔案

| 檔案 | 用途 |
|---|---|
| `q11-data.js` | 由評量表 xlsx 轉出：能力字典、60 款遊戲映射（每款 2 項主要能力＋1 項次要能力）、自評題目、權重。**不要手改**，評量表更新時重新轉檔。 |
| `q11.js` | 計分引擎＋面板 UI（`window.MFQ`） |
| `q11.css` | 面板樣式（沿用成長紀錄的 `gr-*` 元件） |
| `test.js` | 計分規則自動測試：`node q11/test.js` |

## 計分規則（對應評量表「評分規則」SC-01～SC-14）

1. **遊戲分數**：每款遊戲自己的 0–100 分（目前 = 遊戲回報的成績比例 × 100），取該款**最近 3 場**平均。
2. **跨遊戲**：同一能力把有紀錄的各款遊戲**等權平均**，不會因為某款玩很多次而被它壟斷。
3. **只計主要能力**：次要能力 V1.0 不納入。
4. **自我評量**：(答題分數 − 1) ÷ 4 × 100，取最近一次有回答該題的紀錄。
5. **合併**：遊戲 70%＋自評 30%；只有一種資料時就用那一種。兩種都沒有 →「尚待探索」，**不補 0 分**。
6. 每項能力顯示資料完整度（70%／30%／100%）、有效遊戲款數、場數、自評次數、更新時間、計分版本。

計分版本標為 `V1.0-prov`（暫行版）：各遊戲的事件指標還沒定義，所以先用整體成績比例。指標完成後，只要把 `MFQ.record()` 收到的分數改成依指標計算，雷達圖與歷程不必改。

## 資料存放

存在玩家檔案 `p.q11`（`localStorage` 的 `mf-player-v1`），由 `cloud.js` 自動同步到 Supabase 的 `saves` 資料表，換裝置登入就會帶著走。

```js
p.q11 = {
  v: 1,
  ev:   [[時間(秒), 遊戲編號, 分數0–100, 遊玩秒數], ...],   // 最多 3000 筆
  self: [{ t: 時間(秒), a: { HQ: 1–5, ... }, ver: "V1.0" }, ...]
}
```

成長歷程不另外存：每個有紀錄的日子，用當天結束時的資料即時重算。

## 資料從哪裡進來

- **遊戲**：平台的 `rewardResult()`，每場有效遊戲（≥ 30 秒）自動呼叫 `MFQ.record(p, 遊戲編號, 分數, 秒數)`。迷宮尋寶、記憶星球、外部遊戲回傳的成績都會走這條路。
- **自我評量**：面板上的「📝 自我評量」，11 題五點量表，可以略過不確定的題目。

## 待確認清單

- 每款遊戲要回報哪些事件、各指標的計分方向與標準化方式（評量表「指標評分設定範本」目前都是「待定義」）
- TQ、NQ 要有多人互動事件才算遊戲分數；在多人模式完成前，只能靠自我評量
- 自評題目每項目前只有 1 題，評量表建議擴充到 3–5 題
- 70／30 權重、進階解鎖門檻 60 分，試行後是否調整
- 之後老師／機構要看班級資料時，再把 `p.q11` 拆成正式資料表並套用 RLS
